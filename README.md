# Экзаменационный центр

Консольная информационная система на Java и PostgreSQL для КР 1. Основная сущность — заявка на экзамен. Кандидат может иметь несколько заявок. Все данные хранятся в PostgreSQL и экспортируются в Excel.

## Быстрый запуск на этом компьютере

В папке проекта выполните:

```bash
./run.sh
```

Скрипт запускает отдельный PostgreSQL 16 в `.local-db` на `127.0.0.1:55432`. При первом создании базы он создаёт таблицы и учебные записи, затем открывает меню. При последующих запусках изменения данных сохраняются. JDK 17 и Maven уже установлены. Для выхода выберите `0`. База продолжает работать; остановить её можно командой:

```bash
/opt/homebrew/opt/postgresql@16/bin/pg_ctl -D .local-db stop -m fast
```

## Запуск на другом компьютере

Нужны Java 8 или новее, Maven и PostgreSQL. Создайте базу и выполните SQL-скрипты:

```bash
createdb -U postgres exam_center
psql -U postgres -d exam_center -f sql/schema.sql
psql -U postgres -d exam_center -f sql/seed.sql
```

Передайте параметры подключения и запустите приложение:

```bash
export EXAM_DB_URL='jdbc:postgresql://localhost:5432/exam_center'
export EXAM_DB_USER='postgres'
export EXAM_DB_PASSWORD='ваш_пароль'
mvn compile exec:java
```

Значения по умолчанию: URL `jdbc:postgresql://localhost:5432/exam_center`, пользователь `postgres`, пустой пароль. Maven загружает JDBC-драйвер PostgreSQL и библиотеку Apache POI для записи `.xlsx` из `pom.xml`.

## Что умеет программа

- Добавлять и просматривать кандидатов.
- Создавать, просматривать, изменять и удалять заявки.
- Согласовывать, завершать и отменять заявки.
- Искать заявки по экзамену и ФИО кандидата.
- Фильтровать по статусу и диапазону дат.
- Сортировать по дате экзамена и ФИО кандидата.
- Показывать статистику: число кандидатов, всех заявок, заявок по каждому из четырёх статусов и будущих активных экзаменов.
- Показывать структуру и содержимое таблиц PostgreSQL.
- Экспортировать актуальные данные БД в `.xlsx` с листами «Кандидаты» и «Заявки».

После каждого действия программа возвращается в меню. Файл Excel по умолчанию создаётся в `export/exam_center.xlsx`.

## Где находится логика

```text
ConsoleUi → ExamCenterService → ExamCenterRepository → PostgreSQL
                  ↓                      ↓
             model и enum          JDBC и SQL-запросы
```

В `src/main/java/ru/mirea/examcenter` всего 9 Java-файлов. Для понимания программы начните с `Main → ConsoleUi → ExamCenterService → ExamCenterRepository`.

| Файл | Назначение |
| --- | --- |
| `Main.java` | Проверяет подключение, связывает компоненты и запускает меню. |
| `ui/ConsoleUi.java` | Читает ввод, показывает меню и результаты, обрабатывает ошибки. |
| `service/ExamCenterService.java` | Проверяет правила, выполняет операции с кандидатами и заявками, поиск, фильтрацию, сортировку и статистику. Внутри находится собственное исключение `BusinessException` для понятных ошибок. |
| `repository/ExamCenterRepository.java` | Открывает JDBC-соединения, выполняет параметризованные SQL-запросы и читает метаданные таблиц. |
| `model/Applicant.java` | Данные кандидата. |
| `model/ExamApplication.java` | Данные заявки и связанного кандидата. |
| `model/ApplicationStatus.java` | Статусы `NEW`, `APPROVED`, `COMPLETED`, `CANCELLED`. |
| `export/DataExporter.java` | Интерфейс экспорта. |
| `export/XlsxExporter.java` | Реализация экспорта через Apache POI. |

`sql/schema.sql` создаёт две связанные таблицы и ограничения, `sql/seed.sql` добавляет 5 кандидатов и 10 заявок с четырьмя статусами. `docs/er-diagram.svg` и `docs/er-diagram.md` содержат ER-диаграмму и её описание.

Разделение на меню, сервис и репозиторий нужно по ТЗ: SQL находится только в репозитории, правила — в сервисе. `DataExporter` оставлен отдельным интерфейсом, потому что ТЗ требует интерфейс и полиморфизм; `XlsxExporter` реализует его. Каталоги `.idea`, `.local-db`, `.maven-cache` и `target` содержат настройки IDE, локальную БД, зависимости и результаты сборки. Их не нужно изучать для объяснения логики.

## Бизнес-правила

1. ФИО содержит 2–120 символов, email имеет корректную форму и уникален.
2. Заявка может ссылаться только на существующего кандидата.
3. Название экзамена содержит 2–120 символов.
4. Новую или изменённую заявку можно назначить только на будущее время.
5. У кандидата не может быть двух активных заявок на один экзамен в одно время.
6. Разрешены переходы `NEW → APPROVED/CANCELLED` и `APPROVED → COMPLETED/CANCELLED`.
7. Завершённые и отменённые заявки нельзя изменять.
8. Завершить экзамен можно только после назначенного времени с баллом 0–100. При других статусах балл отсутствует.

Правила проверяются в `ExamCenterService`. Ключевые ограничения продублированы в PostgreSQL. Интерфейс обрабатывает неверные числа и даты, ошибки правил и ошибки SQL без аварийного завершения.

## Проверка и материалы к защите

Сборка:

```bash
mvn clean package
```

После запуска базы интеграционная проверка на этом компьютере:

```bash
EXAM_DB_URL='jdbc:postgresql://127.0.0.1:55432/exam_center' \
EXAM_DB_USER=postgres \
mvn -Dexec.mainClass=ru.mirea.examcenter.IntegrationSmoke \
    -Dexec.classpathScope=test exec:java
```

Проверка создаёт временного кандидата и заявку, проходит CRUD, ограничения, поиск, фильтры, сортировки, статистику, просмотр таблиц и Excel, затем удаляет тестовые записи. Учебные 5 кандидатов и 10 заявок остаются в базе.

Для защиты подготовлены исходный код, `pom.xml`, SQL-скрипты, ER-диаграмма, рабочее меню, инструкция и `outputs/exam-center/from_database.xlsx`, экспортированный из PostgreSQL.
