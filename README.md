# Экзаменационный центр — КР 1

Консольная Java-система с PostgreSQL. В проекте три сущности для трёх участников команды: **кандидат**, **заявка на экзамен**, **экзаменатор**. Кандидат связан с заявками отношением один ко многим. Экзаменаторы ведутся как отдельный справочник сотрудников.

## Быстрый запуск

На этом компьютере в папке проекта:

```bash
./run.sh
```

Скрипт запускает локальный PostgreSQL на порту `55432`, применяет `sql/schema.sql`, один раз загружает учебные данные из `sql/seed.sql` и открывает консольное меню. Существующие пользовательские записи сохраняются. Для выхода выберите `0`.

На другом компьютере нужны Java 8+, Maven и PostgreSQL. Создайте БД `exam_center`, выполните `sql/schema.sql` и `sql/seed.sql`, затем задайте `EXAM_DB_URL`, `EXAM_DB_USER`, `EXAM_DB_PASSWORD` и запустите `mvn compile exec:java`.

Проверка сборки: `mvn clean package`. Интеграционная проверка на работающей БД:

```bash
EXAM_DB_URL='jdbc:postgresql://127.0.0.1:55432/exam_center' \
EXAM_DB_USER=postgres \
mvn -Dexec.mainClass=ru.mirea.examcenter.IntegrationSmoke \
    -Dexec.classpathScope=test exec:java
```

## Структура проекта

Все Java-файлы лежат под `src/main/java/ru/mirea/examcenter`. Это корректный пакет проекта; `pom.xml` задаёт группу `ru.mirea`, Java 8, главный класс, JDBC-драйвер PostgreSQL и Apache POI для Excel.

```text
Main → ConsoleUi → ApplicantService       → ApplicantRepository       → PostgreSQL
                 → ExamApplicationService → ExamApplicationRepository → PostgreSQL
                 → ExaminerService        → ExaminerRepository        → PostgreSQL
                 → DataExporter → XlsxExporter → Excel
```

| Где находится | За что отвечает |
| --- | --- |
| `Main.java` | Создаёт сервисы и проверяет подключение. |
| `ui/ConsoleUi.java` | Меню, ввод, вывод и сообщения об ошибках. |
| `model/Applicant.java`, `ExamApplication.java`, `Examiner.java` | Частные поля, конструкторы, геттеры и сеттеры трёх сущностей. |
| `model/ApplicantStatus.java`, `ApplicationStatus.java`, `ExaminerStatus.java` | Enum допустимых статусов каждой сущности. |
| `service/ApplicantService.java`, `ExamApplicationService.java`, `ExaminerService.java` | Правила, CRUD, поиск, фильтры, сортировки. В каждом сервисе объявлено своё исключение для понятных ошибок. |
| `repository/ApplicantRepository.java`, `ExamApplicationRepository.java`, `ExaminerRepository.java` | SQL-операции своей сущности через JDBC. |
| `repository/Database.java` | Единое место для параметров подключения. |
| `export/DataExporter.java`, `XlsxExporter.java` | Интерфейс и его реализация; экспорт трёх листов Excel. |
| `sql/schema.sql`, `sql/seed.sql` | Таблицы, ограничения и тестовые данные: 5 кандидатов, 10 заявок, 5 экзаменаторов. |
| `docs/er-diagram.svg` | ER-диаграмма трёх таблиц. |
| `outputs/exam-center/from_database.xlsx` | Пример экспорта из работающей БД. |

`.local-db`, `.maven-cache`, `target` и `.idea` — локальная база, зависимости, сборка и настройки IDE. При объяснении бизнес-логики их можно пропустить.

## Соответствие требованиям по каждой сущности

| Сущность | CRUD | Enum | Собственное исключение | Поиск и фильтры | Прямая и обратная сортировки | Excel |
| --- | --- | --- | --- | --- | --- | --- |
| Кандидат | создать, список, ID, изменить, удалить | `ApplicantStatus` | `ApplicantException` | ФИО, статус, домен email | ФИО и email | лист «Кандидаты» |
| Заявка | создать, список, ID, изменить, удалить; смена статуса | `ApplicationStatus` | `ApplicationException` | экзамен, ФИО кандидата, статус, даты | дата и ФИО | лист «Заявки» |
| Экзаменатор | создать, список, ID, изменить, удалить | `ExaminerStatus` | `ExaminerException` | ФИО, статус, предмет | ФИО и предмет | лист «Экзаменаторы» |

Сортировки используют Java Collections и `Comparator`, фильтры — Stream API. Все данные сохраняются в PostgreSQL; репозитории работают через `Connection`, `PreparedStatement`, `ResultSet` и `try-with-resources`. SQL нет в консольном меню. Все действия после выполнения возвращают пользователя в то же меню.

## Показ на защите — три участника

Перед показом выполните `./run.sh`. Сначала в каждом разделе выберите `2 — Список`, чтобы увидеть учебные записи и реальные ID. Новые email для демонстрации должны быть уникальными.

**Участник 1 — кандидат.** Откройте пункт `1`. Покажите модель `Applicant`, enum `ApplicantStatus`, классы `ApplicantRepository` и `ApplicantService`. В меню создайте кандидата со статусом `ACTIVE`, получите его по ID, измените телефон или статус, найдите по ФИО, отфильтруйте по статусу и домену email, отсортируйте по ФИО сначала прямо, затем обратно. Удалите именно созданного кандидата, пока у него нет заявок. Для ошибки введите несуществующий ID или повторный email.

**Участник 2 — заявка.** Откройте пункт `2`. Покажите `ExamApplication`, `ApplicationStatus`, `ExamApplicationRepository` и `ExamApplicationService`. Возьмите ID существующего активного кандидата. Создайте заявку на будущую дату, получите по ID, измените название или дату, найдите по экзамену и ФИО, отфильтруйте по статусу и датам, отсортируйте по дате в обе стороны. Согласуйте заявку, затем отмените или удалите свою тестовую заявку. Покажите ошибку на прошедшей дате, дубликате либо запрещённом переходе статуса.

**Участник 3 — экзаменатор.** Откройте пункт `3`. Покажите `Examiner`, `ExaminerStatus`, `ExaminerRepository` и `ExaminerService`. Создайте экзаменатора, получите по ID, измените предмет или статус, найдите по ФИО, отфильтруйте по предмету и статусу, отсортируйте по предмету сначала прямо, затем обратно. Удалите созданного экзаменатора. Для ошибки введите повторный email или неизвестный ID.

**Общая часть.** В главном меню покажите пункт `4 — Статистика`, затем `5 — Экспорт Excel`. Укажите `outputs/exam-center/from_database.xlsx` или нажмите Enter для файла `export/exam_center.xlsx`. Откройте три листа. Пункт `6` показывает таблицы и их данные. На ER-диаграмме объясните внешний ключ `exam_applications.applicant_id → applicants.id`.

### Частые вопросы про заявку

`ExamApplication` объявлен как `final class`. Это запрещает наследоваться от класса. **Поля класса не `final`**: у всех есть геттеры и сеттеры, например `getScheduledAt()` и `setScheduledAt(...)`. Сеттер меняет Java-объект в памяти; для сохранения даты в PostgreSQL используется `ExamApplicationService.updateApplication()` и SQL `UPDATE` в репозитории.

Сортировка заявок есть отдельно **по дате экзамена** (`sortByDate`) и **по ФИО кандидата** (`sortByApplicant`). Параметр `ascending=true` задаёт прямой порядок, `false` — обратный через `Comparator.reversed()`. В разделе заявок это пункты `13` и `14`; после выбора каждого пункта введите `1` для прямой сортировки или `2` для обратной. Интеграционная проверка вызывает все четыре варианта.

## Что нужно знать минимально

1. **Путь команды:** меню получает ввод → сервис проверяет правила → репозиторий выполняет SQL → PostgreSQL хранит данные → результат возвращается в меню.
2. **ООП:** модели имеют `private` поля, конструкторы, геттеры и сеттеры; enum ограничивает статусы; `DataExporter` — интерфейс, `XlsxExporter` его реализация. Это демонстрация полиморфизма через тип интерфейса.
3. **CRUD:** Create — `INSERT`, Read — `SELECT`, Update — `UPDATE`, Delete — `DELETE` в соответствующем репозитории.
4. **Ошибки:** каждый сервис бросает собственное исключение при нарушении правил или неизвестном ID; меню показывает сообщение и продолжает работу. `SQLException` обрабатывается отдельно.
5. **JDBC:** `PreparedStatement` использует `?` и передаёт значения через `set...`; в отличие от обычного `Statement`, данные не склеиваются с SQL-строкой. `try-with-resources` закрывает соединение, запрос и результат.
6. **База:** `applicants.id` и `exam_applications.applicant_id` образуют связь один ко многим. `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK` защищают данные.
7. **Бизнес-правила заявки:** существующий активный кандидат; название 2–120 символов; дата в будущем; нет активного дубликата; допустимые переходы статуса; балл 0–100 только у завершённого экзамена.

В каталоге `src/test/java/ru/mirea/examcenter/IntegrationSmoke.java` есть проверка всех трёх сущностей на реальной базе, включая экспорт. Она создаёт временные записи и удаляет их после проверки.
