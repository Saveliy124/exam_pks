# Экзаменационный центр

КР3: **Spring Boot 3.5.16 / Java 21 → Spring Security и JWT → Spring Data JPA → PostgreSQL 17**. Веб-клиент на HTML/CSS/JavaScript раздается тем же backend. Система продолжает тему и таблицы КР1; отдельный JavaFX-клиент КР2 сохранен.

## Быстрый запуск на Mac

1. Установите JDK 21, Maven 3.9, Docker Desktop и Python 3. Запустите Docker Desktop.
2. В корне проекта откройте **Запустить КР3.command**, либо выполните:

```bash
bash scripts/kr3-start.sh
```

3. Откройте [веб-приложение](http://localhost:8080/).
4. Логин и временный пароль первого администратора: `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD` в локальном `.env`. При первом входе замените пароль; старый пароль из `.env` после этого не действует.

Подготовка автоматически создает случайные секреты, собирает JAR, запускает два Docker-сервиса и применяет Flyway. При наличии работающей прежней КР2 копирует три таблицы в **отдельную базу КР3** один раз. Повторный запуск сохраняет данные. Без КР2 создается чистая база с учебными примерами. Дальнейшей синхронизации баз КР2 и КР3 нет.

`.env`, дампы и личные настройки не публикуются. `.env.example` показывает имена переменных. Секреты нужно сгенерировать на каждой новой машине запуском подготовки. Для остановки: `bash scripts/kr3-stop.sh`. Остановка не удаляет том PostgreSQL.

## Функции

- Роли наблюдателя, оператора и администратора; BCrypt, access JWT, ротация и отзыв refresh, обязательная смена временного пароля и блокировка неудачных входов.
- Заявки с публичным UUID и отдельным кодом, кандидатами, дисциплинами, статусами, результатами, готовностью, документами, тегами и расчетным риском.
- Серверный поиск, комбинированные фильтры, сравнения готовности, разрешенная сортировка и страницы до 100 записей.
- Контроль версий, архив и восстановление; окончательное удаление только администратором с подтверждением.
- Справочники, авторские заметки с закреплением, массовые операции с отдельными результатами.
- CSV: проверка файла отдельным запросом, одноразовое применение, CREATE_ONLY/UPSERT, экспорт всей текущей выборки.
- Аналитика, управление пользователями, аудит с correlation ID, Swagger/OpenAPI, единые ошибки.

## Структура

`web-backend` — новый сервер КР3 с обязательными пакетами, JPA, безопасностью и миграциями. `web` — самостоятельные HTML/CSS/JS модули клиента, npm для запуска не нужен. `common`, `desktop`, `backend` — сохраненная КР2. Ее запуск: **Запустить КР2.command**. Ее документация: [прежнее README](docs/kr3/kr2-readme.md).

Основная сущность — заявка на экзамен, справочная — дисциплина. Старые BIGINT-ключи сохранены внутри таблиц для переноса КР1; публичный REST API использует UUID. База создается и расширяется четырьмя Flyway-миграциями, Hibernate работает с `ddl-auto: validate`. Docker Compose КР3 находится в `web-backend/docker-compose.yml`, КР2 — в корневом `compose.yaml`.

## Проверки

```bash
mvn test
python3 scripts/kr3-test-api.py
python3 scripts/kr3-test-browser.py
```

Первый вызов проверяет чистую логику. Второй пересоздает только выделенную PostgreSQL-базу с суффиксом `_test` и выполняет полную цепочку API. Третий запускает временный backend в Docker и отдельную браузерную базу. Перед ним соберите образ через обычный запуск КР3. Для Playwright установите Node.js, выполните `npm install --prefix web`, затем `cd web && npx playwright install chromium`, либо задайте `KR3_BROWSER_EXECUTABLE` с путем к Chromium-совместимому браузеру. На этом Mac используется изолированный экземпляр Яндекс Браузера.

В GitHub Actions автоматически запускаются unit и PostgreSQL API-проверки. Браузерный прогон доступен локальным скриптом. Результаты и границы проверки: [отчет](docs/kr3/testing.md).
