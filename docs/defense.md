# Защита версии со Spring Boot

Запустите Docker Desktop, затем «Демонстрация КР2.command». Покажите `docker compose --profile demo ps`: PostgreSQL и наши backend-сервисы. Откройте `/actuator/health` демо-сервера 8082, затем окно JavaFX. Разница от исходной КР2: клиент отправляет HTTP-запросы, правила и SQL выполняет собственный Spring-сервер; прямого JDBC из JavaFX больше нет по согласованному изменению задания.

1. Объясните сущности и связь кандидата с заявками; справочник экзаменаторов независим.
2. Добавьте кандидата, покажите пустую форму, неправильный и повторный email, затем корректное сохранение.
3. Создайте будущую заявку, измените её, согласуйте. Покажите отказ завершить будущий экзамен.
4. Запишите 0 или другой допустимый балл прошедшей согласованной заявки. Покажите запрещённый дальнейший переход.
5. Откройте карточку кандидата и его заявки, покажите отказ удаления связанного кандидата и отмену подтверждения.
6. Совместите поиск, статус и период, сортировку по двум колонкам, выгрузите Excel и сравните строки.
7. Измените период статистики; объясните средний только по результатам, null и ноль, долю завершённых.
8. Покажите CRUD экзаменаторов. Приберитесь только в собственных демонстрационных записях.
9. Проследите код: FXML → ApplicationFormController → ApplicationClient → ApiClient → ApiController → ExamCenterFacade → ExamApplicationService → ExamApplicationRepository → PostgreSQL.
10. Покажите серверную проверку отдельно от формы и отчёт тестов. Объясните, что запись сохраняется в PostgreSQL, поэтому перезапуск окна/сервера не стирает её.

Выучите: Spring Boot и встроенный сервер, REST и HTTP-методы/коды, JSON и DTO, внедрение зависимостей, @RestController, @Service, @Transactional, DataSource/Hikari и JDBC, ограничения БД. Со стороны JavaFX: FXML/Controller, ObservableList, фильтры/сортировка, Task, поток UI и обработка ApiException. Все файлы и связи разобраны в Word-руководстве.
