# Инструкция пользователя версии со Spring Boot

## 1. Открытие и завершение работы

Сначала запустите Docker Desktop. Затем в папке проекта откройте **«Запустить КР2.command»** двойным щелчком. Терминал подготавливает PostgreSQL, собирает и запускает наш Spring Boot в Docker, затем запускает Maven-клиент; рабочим интерфейсом становится окно JavaFX. При первом запуске на новом компьютере зависимости скачиваются из интернета. Последующие запуски используют кэш Maven.

Альтернатива: открыть терминал в корне проекта, выполнить `./scripts/setup.sh`, затем `./run.sh`. Запуск из IntelliJ описан в README. Авторизация в нашем приложении не предусмотрена предметной областью КР1: открывается сразу список заявок. Логин из ТЗ относится к учебному Student Hub.

Чтобы закончить работу, закройте окно приложения. Данные сохраняются после каждого успешного действия; отдельной кнопки «Сохранить весь проект» нет. Контейнер PostgreSQL продолжит работать. Для его остановки выполните `docker compose --profile demo down` из папки проекта. Эта команда сохраняет данные. Следующий `setup.sh` снова запустит контейнер.

Не закрывайте приложение в момент сохранения: дождитесь сообщения в нижней строке состояния. Закрытие диалоговой формы во время её сохранения заблокировано.

## 2. Рабочая и демонстрационная базы

| Запуск | База | Назначение |
| --- | --- | --- |
| `Запустить КР2.command`, `./run.sh` | `exam_center`, БД 55433, API 8081 | Рабочие данные, перенесённые из КР1 |
| `Демонстрация КР2.command`, `./scripts/demo.sh` | `exam_center_demo`, БД 55433, API 8082 | Тренировка и показ преподавателю |
| `scripts/test.sh`, `scripts/test-ui.sh` | `exam_center_test`, порт 55433 | Автоматические проверки; их данные очищаются |
| `scripts/sample-client.sh` | `student_hub`, порт 55434 через backend 8080 | Отдельный пример преподавателя |

Демонстрационная база создаётся один раз из `sql/demo.sql`. Есть 6 кандидатов, 10 заявок, 4 экзаменатора, все статусы, результаты 0, 92 и 100 и прошедшая согласованная заявка. Даты вычисляются относительно дня первоначальной подготовки. Позднее они естественно переходят в прошлое. Скрипт не меняет даты существующих записей и не сбрасывает ваши изменения.

В демонстрационном режиме в боковой панели написано «Демонстрационная база», в заголовке окна — «Демонстрация». Для обычной работы закройте её и запустите рабочую КР2. Историческая БД КР1 на порту 55432 сохранена отдельно и больше не является текущей БД приложения.

## 3. Как устроено главное окно

Слева расположены разделы **«Заявки на экзамены»**, **«Кандидаты»**, **«Экзаменаторы»**, **«Статистика»**. Переключение сохраняет фильтры и сортировку раздела. Чтобы начать поиск заново, нажмите «Сбросить».

В таблице нажмите на строку один раз: действия применяются к ней. Без выбранной строки кнопки изменения, просмотра и удаления недоступны. Для заявки дополнительно учитывается её статус. При узком окне длинный текст может сокращаться многоточием; полное значение доступно в карточке или форме изменения. Минимальный размер окна — 1100 × 740. Статистику можно прокручивать вниз.

**«Обновить данные»** получает согласованный снимок трёх таблиц через REST API нашего backend. Сам JavaFX к PostgreSQL не подключается. Используйте её, если другой экземпляр приложения изменил записи или если соединение восстановилось. После собственного сохранения обновление выполняется автоматически. В нижней строке появляются время обновления, результат операции или понятное сообщение об ошибке. Индикатор показывает фоновую работу; повторные операции на это время отключены.

## 4. Кандидаты

### Добавление

Откройте «Кандидаты» → «Добавить». Заполните:

| Поле | Правило |
| --- | --- |
| ФИО | Обязательное; 2–120 символов после удаления пробелов по краям |
| Email | Обязательный; формат `name@example.org`, до 254 символов; уникален среди кандидатов без учёта регистра |
| Телефон | Необязательный; до 30 символов; можно использовать `+`, пробелы, дефисы |
| Статус | «Активен» или «Заблокирован» |

Нажмите «Сохранить». При ошибке форма остаётся открытой: сообщение объясняет проблему, поле подсвечивается. После успешного сохранения форма закрывается, таблица обновляется. Если включён фильтр, не соответствующая ему новая запись будет скрыта: нажмите «Сбросить».

### Редактирование и карточка

Выберите кандидата → «Изменить». В форме уже стоят текущие значения. Измените их и сохраните. Пробелы по краям убираются, email переводится в нижний регистр. Свой email можно оставить без изменения.

«Карточка» показывает ФИО, email, телефон, статус и таблицу всех заявок этого кандидата. Кнопка **«Новая заявка»** открывает форму с уже выбранным кандидатом; для заблокированного она недоступна. **«Показать в разделе заявок»** открывает основной список только с его заявками. В этом списке появляется пояснение о выбранном кандидате; «Сбросить» вернёт всех.

### Блокировка и удаление

Статус «Заблокирован» запрещает создавать или редактировать заявку с этим кандидатом. Его старые записи остаются в базе.

«Удалить» сначала открывает подтверждение. «Отмена» и закрытие окна ничего не меняют. Кандидата нельзя удалить, пока у него есть хотя бы одна заявка, в том числе отменённая или завершённая. Если требуется сохранить историю, измените статус кандидата на «Заблокирован». Для полного удаления сначала удаляют связанные заявки, затем кандидата.

### Поиск и фильтры

Поиск проверяет **ФИО, email и телефон** без учёта регистра. Фильтры — **статус** и **домен email**. Домен вводится целиком, например `example.org` или `@example.org`; `ample.org` не заменяет `example.org`. Поиск и оба фильтра применяются одновременно. «Все статусы» снимает только статусный фильтр; «Сбросить» очищает все условия.

## 5. Заявки на экзамены

### Создание

Нажмите «Добавить» в разделе заявок. Выберите кандидата в выпадающем списке: рядом с ФИО показан email, поэтому однофамильцев можно различить. Вручную вводить ID не нужно. Для новой заявки доступны активные кандидаты. Если список пуст, сначала создайте активного кандидата.

Введите название экзамена (2–120 символов), выберите дату календарём, укажите часы (0–23) и минуты (0–59). Время должно быть строго в будущем. Сервер и штатные команды запуска клиента используют Europe/Moscow; сервер окончательно проверяет время. В PostgreSQL сохранён тип `TIMESTAMP` из КР1 без изменения его смысла.

После сохранения заявка получает статус **«Новая»**, а дата создания назначается базой. Нельзя создать вторую активную заявку тому же кандидату на тот же экзамен и точное время. Регистр названия экзамена не имеет значения; активными считаются «Новая» и «Согласована».

### Просмотр и редактирование

«Карточка» показывает кандидата, экзамен, дату/время, статус, балл и дату создания. В этом режиме данные доступны только для чтения.

«Изменить» позволяет заменить кандидата, название и будущее время у новой или согласованной заявки. Для завершённой и отменённой кнопка недоступна. Если запланированное время уже прошло, для редактирования деталей потребуется указать будущее время. Чтобы записать результат прошедшего экзамена, используйте отдельную кнопку «Записать результат».

### Согласование, результат и отмена

| Текущий статус | Кнопка | Результат |
| --- | --- | --- |
| Новая | «Согласовать» → «Сохранить» | Согласована |
| Новая | «Отменить заявку» → «Сохранить» | Отменена |
| Согласована | «Записать результат» → целый балл 0–100 → «Сохранить» | Завершена |
| Согласована | «Отменить заявку» → «Сохранить» | Отменена |
| Завершена / Отменена | Просмотр и удаление | Дальнейшее изменение статуса запрещено |

Записать результат можно только **после наступления назначенного времени**. Балл 0 допустим и отличается от отсутствия результата. У остальных статусов балла нет. Отмена заявки сохраняет запись и историю; удаление физически убирает запись из базы. Возврат из завершённого или отменённого статуса не предусмотрен исходными правилами КР1.

Для показа результата без ожидания запускайте демонстрационную базу и выбирайте согласованную заявку Дмитрия Козлова на прошедшую дату. Не меняйте вручную часы компьютера или даты рабочих записей ради демонстрации.

### Связанные данные, удаление, поиск

«Кандидат и его заявки» открывает карточку связанного кандидата. «Удалить» удаляет выбранную заявку только после подтверждения; статус на возможность удаления не влияет.

Поиск проверяет **имя кандидата, его email и название экзамена**. Фильтры — **статус** и **период даты экзамена**. Начальную или конечную границу можно не задавать. Обе границы включены: конечный день учитывается целиком. Если начало позже окончания, показывается ошибка, таблица очищается и экспорт блокируется до исправления периода. Статус, период, поисковая строка и фильтр по кандидату работают совместно.

## 6. Экзаменаторы

Это независимый справочник сотрудников из КР1. В исходной схеме нет внешнего ключа от заявки к экзаменатору, поэтому назначение экзаменатора заявке не добавлялось.

«Добавить» открывает форму: ФИО 2–120 символов, уникальный email до 254 символов, предмет 2–120 символов, статус «Активен» / «Неактивен». Все поля обязательны. «Изменить» открывает текущие значения; «Карточка» показывает их без возможности изменения. «Удалить» требует подтверждения.

Поиск работает по **ФИО, email и предмету**. Фильтры: **статус** и **предмет содержит**. Например, `матем` находит «Математика» и «Высшая математика». «Сбросить» очищает все условия. Уникальность email проверяется внутри справочника экзаменаторов; одинаковый email у кандидата и экзаменатора не запрещён схемой КР1.

## 7. Сортировка всех таблиц

Нажмите заголовок нужного столбца. Следующее нажатие меняет направление сортировки; стрелка показывает текущий порядок. Например, в заявках можно сортировать по дате, кандидату, экзамену и баллу; в справочниках — по ФИО, email, статусу и предмету/телефону.

Для сортировки по нескольким полям сначала выберите главное поле, затем удерживайте **Shift** и нажмите второй заголовок. Даты сравниваются как даты, баллы — как числа. Сортировка не изменяет строки в PostgreSQL и сохраняется при фильтрации и обновлении. По умолчанию заявки идут от более поздней даты к ранней, справочники — по имени.

## 8. Статистика

Раздел запрашивает серверный расчёт при открытии, смене периода и обновлении общего снимка. Если записи изменились из другого окна, нажмите «Обновить данные».

| Показатель | Расчёт |
| --- | --- |
| Всего заявок | Все заявки, дата экзамена которых попадает в период |
| Предстоящие экзамены | Новые и согласованные заявки с датой/временем в будущем внутри периода |
| Средний балл | Среднее только по завершённым экзаменам с результатом; отображается один знак после запятой |
| Доля завершённых | Число завершённых / все заявки периода × 100%; отменённые включены в знаменатель |
| Минимальный балл | Минимальный результат завершённых экзаменов |
| Максимальный балл | Максимальный результат завершённых экзаменов |
| Заявки по статусам | Диаграмма и числа новых, согласованных, завершённых, отменённых |
| Кандидатов | Общее количество кандидатов во всей базе, без ограничения периодом |
| Активных экзаменаторов | Количество активных экзаменаторов во всей базе, без ограничения периодом |

Период задаётся **по дате экзамена**, а не по дате создания заявки. «За всё время» снимает обе границы. Когда результатов нет, средний/минимум/максимум показывают `—`, а не выдуманный нулевой результат. При пустом периоде число заявок и доля завершённых равны нулю. Для просмотра диаграммы и нижних показателей при необходимости прокрутите страницу.

## 9. Экспорт в Excel

В любом из трёх разделов с таблицей:

1. Настройте поиск, фильтры и сортировку так, как хотите увидеть их в файле.
2. Нажмите **«Экспорт в Excel»**.
3. В стандартном окне сохранения выберите папку и имя файла. Расширение — `.xlsx`.
4. При необходимости подтвердите замену существующего файла.
5. Дождитесь сообщения в нижней строке с числом записей и путём.

Экспортируется **вся текущая отфильтрованная таблица в текущем порядке**, включая строки ниже области прокрутки. Выбранная строка не ограничивает экспорт. Один экспорт содержит один лист соответствующего раздела. Технические ID не выводятся. В Excel даты остаются датами, баллы — числами; отсутствующий балл — пустой ячейкой. Первая строка закреплена, настроены заголовки и автофильтр.

Если выборка пуста, создаётся файл с заголовками. «Отмена» в окне сохранения ничего не записывает. При неверном диапазоне дат сначала исправьте фильтр. Если папка недоступна или файл нельзя сохранить, появится понятная ошибка. Запись сначала выполняется во временный файл, затем результат заменяет целевой файл.

## 10. Ошибки и восстановление соединения

| Сообщение или ситуация | Что сделать |
| --- | --- |
| Нет соединения с backend | Проверить `docker compose ps`, `docker compose logs backend`, адрес EXAM_API_URL и `/actuator/health`; выполнить `./scripts/setup.sh` и «Обновить данные» |
| Backend сообщает о недоступной PostgreSQL | Проверить `.env` и логи серверов; пароль существующего volume не меняется редактированием `.env` |
| База или таблицы не найдены | Выполнить `setup.sh`; для своей существующей БД применить `sql/schema.sql` |
| Email уже используется | Выбрать другой адрес или редактировать существующую запись |
| Кандидат заблокирован | Выбрать активного кандидата или обоснованно изменить его статус в справочнике |
| Уже есть активная заявка | Изменить время/экзамен либо работать с существующей заявкой |
| Нельзя завершить до назначенного времени | Дождаться экзамена; для показа использовать прошлую заявку демонстрационной базы |
| Нельзя удалить кандидата с заявками | Сохранить его историю через блокировку либо сначала удалить связанные заявки |
| Запись изменена или удалена | Нажать «Обновить данные», выбрать актуальную строку и повторить действие |
| Не удалось сохранить файл | Выбрать существующую доступную папку и повторить экспорт |
| После добавления строка не видна | Проверить фильтры и нажать «Сбросить» |
| JDK 21 не найден | Установить JDK 21; на Windows задать `JAVA_HOME`, на Mac проверить `/usr/libexec/java_home -V` |
| Maven не найден | Установить Maven 3.9+ и открыть новый терминал |
| Порт 55433 занят | Остановить только известный конфликтующий сервис либо выбрать свободный порт в `.env` и повторить подготовку |

Пользователю не показывается Java stack trace. Для диагностики разработчик может посмотреть журнал запуска в терминале. Исходная причина исключения не теряется, а сообщения PostgreSQL с содержимым записей не выводятся в графический интерфейс.

## 11. Резервная копия и восстановление в отдельную базу

Из корня проекта:

```sh
./scripts/backup.sh
```

Путь нового файла вида `backups/exam_center-ДАТА-ВРЕМЯ.dump` появится в терминале. Для проверки восстановления используйте именно свой путь и новое незанятое имя:

```sh
./scripts/restore-copy.sh backups/имя-файла.dump exam_center_restore
EXAM_DB_URL=jdbc:postgresql://127.0.0.1:55433/exam_center_restore EXAM_SERVER_PORT=8083 ./scripts/backend-local.sh
# В другом терминале:
EXAM_API_URL=http://127.0.0.1:8083 ./run.sh
```

Восстановление допускается только в новую БД с суффиксом `_restore`. При занятом имени скрипт откажется продолжать. Рабочая база не перезаписывается. При запуске отдельного backend с ручным `EXAM_DB_URL` вы самостоятельно выбираете целевую БД; JavaFX выбирает только HTTP-адрес через `EXAM_API_URL`. Для возврата к обычной базе закройте приложение и выполните `./run.sh` без переменной.

## 12. Учебный пример и старый интерфейс

Полная инструкция Student Hub находится в [instructor-example.md](instructor-example.md). Его логин, студенты и группы относятся к учебному примеру и не добавляются в «Экзаменационный центр».

Консоль КР1 сохранена для сравнения: `./scripts/run-console.sh`. Она расположена в серверном модуле и использует прямой JDBC только как диагностическая утилита. Графический клиент работает через REST. Основной интерфейс КР2 — JavaFX. На защите операции выполняются в графическом окне.

## 13. Короткая репетиция

Запустите демонстрацию. Создайте кандидата с новым email, добавьте ему заявку на завтра, измените название, согласуйте, попробуйте завершить слишком рано и покажите ошибку. Запишите результат прошедшей согласованной заявки. Примените поиск + статус + период, отсортируйте строки и экспортируйте Excel. Покажите карточку кандидата со связанными заявками, статистику, отказ удаления связанного кандидата и отмену подтверждения. Затем удалите свою тестовую заявку и своего тестового кандидата.
