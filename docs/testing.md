## Как проводились проверки

`./scripts/test.sh` прошёл модульные, JDBC и HTTP-тесты. `./scripts/test-ui.sh` прошёл на локальном тестовом Spring HTTP-сервере. Затем `./scripts/test-docker-ui.sh` повторил весь UI-сценарий через **отдельный Docker-контейнер нашего backend**, связанный с той же *_test БД. JavaFX оставался на Mac. Перед внешним прогоном TestServer проверяет /api/info: сервер должен быть подключён к ожидаемой тестовой БД, не рабочей.

UI-сценарий открывает все разделы и FXML, создаёт/меняет/удаляет кандидата и экзаменатора, создаёт/изменяет/согласовывает/отменяет заявку, записывает результат прошедшего экзамена, проверяет запреты, связанные карточки, совместные фильтры, сортировку, Excel и ошибку записи файла. Проверены пустая форма, неверный email, повторный email, недопустимый час, прошлая дата, раннее завершение и балл 101. При недоступном адресе API окно остаётся открытым; после восстановления обновление снова работает. Статистика проверена с нормальным, пустым и неверным периодом. Минимальное окно и карточки сохранены в снимках.

При переходе на упакованные модули исправлена загрузка FXML через явный classloader. Асинхронная статистика использует номер запроса, чтобы ответ старого периода не перезаписал новый. UI-тест ожидает завершение серверных запросов перед следующей операцией.

## Docker и сохранность данных

Рабочий backend 8081 и demo-backend 8082 прошли healthcheck; оба возвращают свой /api/info и /api/snapshot. Повторная setup.sh сохраняет записи. Данные рабочей БД сравнены построчно с восстановленной в отдельную временную БД копией до миграции: совпали все 6 кандидатов, 10 заявок и 5 экзаменаторов. Рабочий volume сохранён. Временная проверочная копия после сверки удалена.

Runtime-дерево зависимостей desktop проверено: нет PostgreSQL-драйвера и серверного Spring backend. Переносимая копия исходников дополнительно проверяется scripts/verify-release.py: распаковка в папку с пробелами, независимый Compose-проект/volume/порты, пустая БД, повторная подготовка без дублирования и JUnit API-проверки. Хеш протестированного кода сверяется с кодом проекта. Результат в qa/release-check.json.

## Границы проверки

Windows/PowerShell и Linux не запускались в этой сессии. UI-проверки относятся к macOS Apple Silicon. Нагрузочное тестирование больших объёмов и авторизация/роли в текущий объём не входят. Графические и интеграционные сценарии нельзя запускать одновременно: они разделяют *_test БД. Насильственное закрытие клиента в момент сохранения не является доказательством отмены HTTP-запроса; после сетевой ошибки нужно перечитать данные перед повтором.
