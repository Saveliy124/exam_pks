# Учебный пример преподавателя: развёртывание и проверка

Полученный от пользователя `student-hub-suite.zip` распакован целиком в `student-hub-suite-rebuilt/` рядом с нашим `pom.xml`. Сохранены `backend`, `javafx-client` и `android-client`. Это отдельный проект Student Hub; его база не заменяет `exam_center`.

## Установленные отличия архива от текста требований

В скачанной версии `.env` находился в `backend/`. Для запуска по ТЗ создан его локальный экземпляр в корне учебного проекта. У PostgreSQL в исходном compose был опубликован внутренний порт 5433, хотя сервер слушает 5432. Исправление находится в отдельном `docker/sample-override.yaml`; исходные файлы преподавателя не переписываются.

Внешний порт установлен 55434, чтобы не конфликтовать со старой БД КР1 на 55432 и текущей БД КР2 на 55433. Дополнительный сервис `connection-info` штатно завершается с кодом 0; поэтому команда ожидания запускает только долгоживущие `db` и `backend`. Это исключает ложную ошибку `--wait` после успешного запуска серверной части.

## Повторный запуск на этом Mac

Из корня нашего проекта:

```sh
./scripts/sample-start.sh
./scripts/sample-client.sh
```

Первый скрипт готовит локальную конфигурацию, запускает PostgreSQL и Spring Boot в Docker и проверяет health endpoint. Второй запускает учебный JavaFX-клиент на компьютере, используя JDK 21 и Maven. Требуется Docker Compose 2.24.4+ для `!override`; здесь проверена версия 5.5.1.

| Компонент | Адрес |
| --- | --- |
| Web | `http://localhost:8080/` |
| Состояние сервера | `http://localhost:8080/actuator/health` |
| REST API | `http://127.0.0.1:8080/api` |
| PostgreSQL примера с Mac | `jdbc:postgresql://127.0.0.1:55434/student_hub` |

Backend использует `jdbc:postgresql://db:5432/student_hub` внутри Docker-сети. JavaFX обращается к REST API и не запускает сервер самостоятельно. Текущая версия «Экзаменационного центра» обращается по REST к собственному Spring Boot на 8081/8082; этот сервер использует JDBC к своей БД.

## Вход

Логин администратора: `admin@example.org`. При первом проверочном входе система потребовала заменить временный пароль. Это действие выполнено через её штатную веб-форму. Текущие данные для локального примера сохранены в **`student-hub-suite-rebuilt/.local-admin.env`**. Откройте файл в текстовом редакторе и используйте значение `DEMO_ADMIN_PASSWORD` в Web или JavaFX. Файл с ограниченными правами доступа не включается в Git и наш архив исходников. Старый bootstrap-пароль из `.env` уже не является текущим паролем этой БД.

На новом развёртывании без существующего volume используйте bootstrap-данные из своего учебного `.env`, а затем задайте постоянный пароль в интерфейсе. Изменение `.env` не меняет пароль уже существующего администратора.

## Фактическая проверка

19.10.2026: оба контейнера healthy; `/` вернул HTTP 200; `/actuator/health` вернул `UP`. Выполнены вход администратора и просмотр аналитики, студентов и групп в Web. Нативный JavaFX-клиент вошёл тем же пользователем и показал MainView, пять вкладок администратора и таблицу студентов. Шесть модульных тестов JavaFX-примера прошли. Снимки и результаты находятся в `docs/qa/`.

Изучены `StudentHubFxApplication`, `LoginView`, `MainView`, табличные панели, диалоги, `FxTasks`, `ApiClient`, `app.css`. Пример создаёт многие экраны программно; собственные ключевые окна вынесены в FXML в соответствии с ТЗ. Android сохранён без изменений, его запуск для КР2 не требуется.

Остановка примера без удаления его данных:

```sh
./scripts/sample-stop.sh
```

При передаче нашего архива на другой компьютер учебный архив нужно отдельно скачать с курса и распаковать целиком в `student-hub-suite-rebuilt/`. `sample-prepare.sh` найдёт `backend/.env` и подготовит корневой `.env`; секреты текущего Mac переносить в общедоступный архив не следует.
