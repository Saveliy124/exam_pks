# Архитектура Spring Boot и JavaFX

Главный путь: `FXML → FX Controller → HTTP Client → REST Controller → ExamCenterFacade → Service → Repository → PostgreSQL`.

## Модули

`common` содержит только обычную Java: модели, enum-статусы, входные/выходные DTO `ApiContracts`, правила `Rules`, `ValidationException`, фильтры, расчёт статистики и Excel. `backend` зависит от common и содержит сервер Spring Boot, три предметных сервиса и SQL-репозитории. `desktop` зависит от common и содержит только JavaFX и HTTP-клиенты. Runtime-зависимости desktop не содержат backend и PostgreSQL JDBC-драйвер. Backend использует desktop только в test-scope для сквозных UI-проверок.

## Сервер

`BackendApplication` запускает встроенный HTTP-сервер. `BackendConfiguration` создаёт предметные сервисы и передаёт репозиториям `TransactionAwareDataSourceProxy` над Spring DataSource. Hikari управляет пулом соединений. `ExamCenterFacade` задаёт границы `@Transactional(rollbackFor=Exception.class)`: несколько обращений предметного сервиса используют одно транзакционное соединение, а закрытие JDBC-обёрток возвращает управление Spring. Проверка отката присутствует в `RestApiIT`.

`CenterRepository` читает три таблицы в отдельной read-only REPEATABLE READ транзакции и возвращает согласованный `CenterSnapshot`. Поэтому snapshot и статистика вызываются без внешней транзакции Spring. Существующие FK, UNIQUE, CHECK и SQL-проверки ожидаемого статуса сохранены. Все операции используют ту же БД КР1; новой независимой рабочей базы не создаётся.

`ApiController` описывает маршруты; входные record DTO не позволяют прислать произвольный ID или дату создания записи. `ApiExceptionHandler` переводит ошибки в JSON `{code, field, message}`: 400 для неправильного ввода, 404 для отсутствующей записи, 409 для конфликтов БД, 503 при потере БД. Сервисная проверка дубля до SQL может вернуть 400, ограничение уникальности при конкурентной вставке — 409. Сырые сообщения PostgreSQL и stack trace в ответ не попадают.

## Клиент

`AppContext` создаёт `ApiClient`, `ApplicantClient`, `ExaminerClient`, `ApplicationClient`; репозиториев в клиенте нет. `ApiClient` использует Java HttpClient и Jackson, имеет тайм-ауты и не повторяет мутации автоматически. Ошибка поля превращается в общую `ValidationException`, поэтому существующая форма умеет выделить поле. Сетевые ошибки представлены `ApiException`.

После сохранения `AppContext.refresh` получает `/api/snapshot` в фоне и меняет ObservableList на JavaFX thread. Запрошенное во время чтения повторное обновление ставится в очередь. UI-контроллеры сохраняют прежние функции. `StatisticsController` запрашивает `/api/statistics` в фоне; счётчик запросов исключает показ ответа от устаревшего периода. Недоступность сервера очищает показатели и показывает ошибку.

`FilteredList → SortedList → TableView` остаётся локальной обработкой последнего снимка. Excel создаётся на Mac из копии именно текущей выборки и её порядка. Эти операции не требуют отдельного SQL или обращения к REST на каждое нажатие клавиши.

## Docker и конфигурация

Compose сохраняет прежнее имя проекта и volume `exam-center-kr2_exam_data`. PostgreSQL слушает 5432 внутри сети и 55433 на localhost Mac. Backend слушает 8081 и опубликован только на localhost. `backend-demo` использует тот же образ и отдельную БД `exam_center_demo`, опубликован на 8082. `HealthProbe` позволяет JRE-образу проверять `/actuator/health` без установки curl. Приложение контейнера работает под UID 10001.

Пароль передаётся через `.env` и переменные окружения, не встраивается в JAR/образ/архив. `.dockerignore` ограничивает контекст сборки. Параметры клиента не содержат пароль БД. Старый `Database` и console Main оставлены в серверном модуле только для самостоятельных JDBC-тестов и диагностики КР1; JavaFX их не использует.

## Границы версии

Нет авторизации и ролей, серверной пагинации и полного optimistic locking для редактирования всех полей. Смена статуса защищена SQL-проверкой исходного статуса; уникальность и связи — ограничениями БД. Время экзамена сохраняет исходный `TIMESTAMP`/`LocalDateTime`, сервер и клиент используют Europe/Moscow. Это учебное локальное приложение; эти границы не выдаются за промышленную систему.
