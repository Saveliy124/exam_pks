# КР3 Экзаменационный центр

КР3 продолжает учет кандидатов, экзаменаторов и заявок из КР1. Теперь сотрудник работает в браузере. JavaFX КР2 сохранен отдельным клиентом со своим прежним сервером. Базы разделены: существующие записи переносятся в КР3 один раз, дальнейшей автоматической синхронизации между КР2 и КР3 нет.

## Запуск на Mac

Нужны Docker Desktop, JDK 21, Maven 3.9 и Python 3 для скриптов подготовки. Node.js нужен только для браузерных тестов. Откройте Docker Desktop, затем запустите `Запустить КР3.command`. Терминальный вариант из корня: `bash scripts/kr3-start.sh`.

Скрипт создает недостающие случайные секреты в корневом `.env`, поднимает PostgreSQL 17, при первом запуске копирует три таблицы из работающей КР2, собирает сервер и запускает его в Docker. Исходный контейнер КР2 и его том не изменяются. Если КР2 отсутствует, Flyway создает чистую схему с небольшим учебным набором данных. При повторном запуске записи сохраняются.

Откройте http://localhost:8080/. Логин первого администратора находится в `BOOTSTRAP_ADMIN_EMAIL`, временный пароль — в `BOOTSTRAP_ADMIN_PASSWORD` корневого `.env`. После входа замените его своим паролем и войдите заново. Начальный пароль из `.env` после этого больше не подходит. Секреты не включаются в GitHub.

Пароль: минимум 12 символов, буквы двух регистров, цифра и специальный символ; максимум 72 байта UTF-8. Пароль не должен содержать логин. Все пароли сохраняются как BCrypt-хеши. При смене и сбросе пароля прежние access-токены и refresh-сессии становятся недействительными.

Для остановки выполните `bash scripts/kr3-stop.sh`. Обычный `docker compose down` сохраняет том базы. Не используйте `down -v`, если хотите сохранить данные. PostgreSQL КР3 опубликован только на localhost, порт 55435; приложение — порт 8080. Сервер КР2 остается на 8081, его демо — на 8082.

## Роли

Наблюдатель VIEWER просматривает заявки, справочники, заметки и аналитику, экспортирует CSV. Оператор OPERATOR дополнительно создает и меняет кандидатов и заявки, архивирует и восстанавливает, работает с заметками, массовыми операциями и импортом. Администратор ADMIN также меняет дисциплины и экзаменаторов, управляет пользователями, читает аудит и Swagger, окончательно удаляет архивные заявки. Сервер проверяет права независимо от видимости кнопок.

## Обзор

На странице «Обзор» показаны общее число заявок, активные записи, архив и число заявок с проверенными документами. Активная запись означает запись вне архива, независимо от статуса экзамена. Средняя готовность и группировки по дисциплине, статусу и риску учитывают все записи. Кнопка «Обновить» запрашивает свежие данные.

## Кандидаты и экзаменаторы

В «Кандидатах» нажмите «Новый кандидат», заполните ФИО, уникальный email и при необходимости телефон. Статусы: активен и заблокирован. Заблокированному кандидату нельзя создать или отредактировать заявку; его история остается. Изменение кандидата доступно оператору и администратору.

«Экзаменаторы» — сохраненный из КР1 справочник сотрудников с ФИО, email, предметом и активностью. Изменяет его администратор. Связь конкретного экзаменатора с заявкой в исходной модели отсутствует и не добавлялась.

## Дисциплины

Администратор добавляет дисциплину с уникальными кодом и названием. «Отключить» запрещает новые заявки по этой дисциплине; уже существующие заявки сохраняются. «Включить» возвращает ее в список доступных для записи. При переносе КР1 дисциплины создаются из имеющихся названий экзаменов с кодами LEGACY. Физического удаления дисциплин нет.

## Заявки

Нажмите «Новая заявка». Укажите отдельный код, кандидата, дисциплину, московскую дату и время, готовность от 0 до 100, отметку документов и при необходимости теги. UUID создается сервером и виден в карточке; код вводит сотрудник. Создать заявку можно только в статусе «Новая» и на будущее время. Один кандидат не может иметь две активные заявки на ту же дисциплину и точное время.

Кнопка «Карточка» показывает сведения, UUID, время создания и изменения, текущую версию и теги. У незакрытой активной заявки доступно «Изменить». Статусы: Новая → Согласована → Завершена. Новую или согласованную можно отменить. Для завершения нужны прошедшее время экзамена и целый результат 0–100. Нулевой балл является результатом; пустое поле означает отсутствие результата. Завершенные и отмененные заявки нельзя редактировать обычной формой.

Риск вычисляет сервер: для завершенных и отмененных он не применяется. Без документов при готовности ниже 30 риск критический; без документов или при готовности ниже 50 — высокий; с документами и готовностью 50–79 — средний; с документами и готовностью 80–100 — низкий. Риск нельзя подставить в JSON вручную.

Каждое изменение передает сохраненную `version`. Если другой сотрудник успел изменить запись, сервер отвечает 409. Обновите список, откройте актуальную карточку и повторите изменение осознанно. Это относится также к архиву, восстановлению, заметкам и массовым операциям.

## Поиск и фильтры

Поиск проверяет код заявки, название экзамена, имя и email кандидата. Все фильтры можно сочетать: дисциплина, статус, документы, риск, тег, архив и готовность. Для числового фильтра выберите оператор сравнения и укажите число. Затем нажмите «Применить». «Сбросить» очищает ограничения. Сортировка доступна по дате, коду, кандидату, готовности, статусу и изменению. Сервер выдает только запрошенную страницу; максимальный размер — 100.

## Архив и окончательное удаление

«В архив» сохраняет запись и заметки, убирая ее из обычного списка. Выберите фильтр «Архивные» или «Все записи», чтобы увидеть ее. «Восстановить» возвращает запись; при конфликте с существующей активной заявкой сервер сообщит об ошибке. Администратор может открыть архивную карточку и выбрать окончательное удаление. Нужно вручную повторить код заявки. Удаление также удаляет теги и заметки. Операцию можно отключить настройкой PERMANENT_DELETE_ENABLED.

## Заметки

Откройте карточку → «Заметки». Доступны история автора и времени, создание, изменение текста, закрепление и удаление. Закрепленные заметки стоят первыми. Оператор изменяет свои заметки; администратор также может менять чужие. Наблюдатель только читает. Текст отображается как текст, HTML-код не выполняется.

## Массовые действия

Отметьте заявки флажками на текущей странице и нажмите «Массовое действие». Можно архивировать, восстановить, изменить статус, добавить или убрать один тег. Для смены на «Завершена» нужен балл; правила времени и переходов те же. Сервер обрабатывает каждую запись в отдельной транзакции. Итог показывает количество успешных операций и ошибки по отдельным кодам. Выбор очищается при обновлении страницы.

## CSV

Экспорт на странице заявок и в «Импорте и экспорте» использует текущие фильтры заявок и выгружает все найденные строки, а не только видимую страницу. Формат — UTF-8 с BOM. Значения, похожие на формулы электронных таблиц, экранируются. Порядок экспорта стабильный по внутреннему ключу.

Скачайте образец CSV, заполните строки и выберите режим. CREATE_ONLY создает только новые коды. UPSERT создает отсутствующие и обновляет имеющиеся по externalId. Перед импортом кандидат и дисциплина должны существовать. Максимум 1000 строк и 2 МБ. Колонки в точном порядке: externalId, applicantEmail, disciplineCode, scheduledAt, status, score, preparationPercent, documentsVerified, tags. Дата — ISO без часового пояса, например 2030-12-20T10:00, по Москве. Логический признак — true или false; теги разделяются |.

Нажмите «Проверить файл». Сервер возвращает корректные и ошибочные строки с номерами, сохраняет проверенные данные на 15 минут и связывает их с вашим пользователем. «Применить корректные строки» запускает импорт один раз. Строки с ошибками проверки не применяются. Если между проверкой и применением запись изменили, соответствующая строка будет отклонена по версии. Повторное применение одного preview запрещено. Закрытые и архивные заявки обновлять импортом нельзя.

## Пользователи

Администратор создает пользователя с именем, email, ролью и временным паролем. Сервер пароль не возвращает; передайте его пользователю отдельно. При первом входе смена обязательна. В «Изменить» доступны имя, логин, роль и активность. Отключенная запись не может войти, ее прежние токены перестают работать. Администратор не может отключить себя или снять собственную роль ADMIN.

«Сбросить пароль» устанавливает новый временный пароль, отзывает прежние токены, сбрасывает блокировку и снова требует смены при входе. Пять неверных попыток временно блокируют вход. Неудачные попытки сохраняются даже при отказе основного запроса.

## Аудит и профиль

В журнале администратор видит входы, изменения данных, сотрудника, тип сущности, время и correlation ID. Доступны поиск, сортировка и страницы. В ошибках отображается код обращения — его можно найти в аудите и серверном журнале. Пароли, токены и полный текст CSV в аудит не записываются.

В профиле можно посмотреть роли и заменить постоянный пароль. После замены потребуется повторный вход. Администратору доступна ссылка Swagger. Раздел открывается через специальный короткоживущий HttpOnly cookie; для Try it out можно авторизоваться access JWT через Authorize. OpenAPI JSON находится по /v3/api-docs, health — по /actuator/health.

## Проверка и защита

Запуск API-тестов: `python3 scripts/kr3-test-api.py`. Они пересоздают только базу с суффиксом `_test`, применяют реальные миграции и проверяют Spring Security, REST, бизнес-правила и PostgreSQL. Чистые тесты: `mvn test`. Браузерные: `python3 scripts/kr3-test-browser.py` после сборки Docker-образа. Они поднимают временный сервер и отдельную тестовую базу. Для браузера установите зависимости `npm install --prefix web`, затем `npx --prefix web playwright install chromium`, либо задайте KR3_BROWSER_EXECUTABLE. На этом Mac тесты используют отдельный экземпляр Яндекс Браузера без доступа к личному профилю.

На защите покажите Docker и health, вход и обязательную смену пароля, три роли, заявку и конфликт версий, фильтры, страницы, архив и восстановление, массовую операцию, заметки, CSV с ошибочной строкой, аналитику, пользователя, аудит, Swagger и SQL-миграции. Объясните путь запроса: браузер → REST-контроллер → сервис и транзакция → Spring Data JPA → PostgreSQL.
